科研与项目

非连续 KV Cache 复用与 GPU Attention 优化

vLLM / FlashInfer / CUDA
  • 实现非连续 KV Cache 复用与 packed-query 执行，贯通缓存安装、worker 输入、Attention metadata 与输出回填，支持 dense/MSA 混合 batch。
  • 开发逐行位置 mask 与短段分组策略，保留原始 token 位置和 causal 语义。在 H20、BF16 构造 workload 的 8/16/32 个重算洞场景中，单层 Attention 加速 1.59/2.28/2.68 倍，采用 CUDA event 与 12 轮配对计时。
  • 40/40 项 GPU 检查通过，覆盖 FP16/BF16、NHD/HND 与 tile 边界；通过 wrapper 池化和共享 workspace 降低测试峰值显存。

Oracle-MWF：面向未来复用的 KV Cache 淘汰

C++ / Python / pybind11
  • 实现 C++ 双索引最小堆，将重计算成本、复用概率与等待折扣转化为双静态键和公共时间偏移，单块增删改与淘汰为 O(log n)。
  • 通过 pybind11 接入 Python 管理器与 BlockPool，联动分配、touch、释放、覆盖和 reset，维护空闲物理副本的反向索引。
  • 构建 28 个会话、3,197 条请求的冻结合成参考数据与跨会话访问索引，完成摘要、反向映射和 CPU 回放校验。

多后端推理调度与可复现基准评估

ThunderAgent / vLLM / Python
  • 搭建四后端 OpenAI 兼容服务与并发回放工具，对比 RR、Sticky-RR 与 ThunderAgent，分析负载均衡和 KV 复用的权衡。
  • 适配 ThunderAgent 与 vLLM 0.22.1 生命周期接口，实现 trace-informed CacheWise 基线，贯通请求元数据、scheduler 与 BlockPool。
  • 冻结 8 个 Program、243 个 turn 的共享 workload，在 Llama-3.1-8B 上完成 5 组配置、每组 3 次有效重复，统计 TTFT、JCT、吞吐与缓存命中并核对机制日志。
